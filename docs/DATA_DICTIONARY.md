# Data dictionary

The tracker stores three tables as CSV files in `data/`. Each **pot** gets one row in `pots.csv` and stays there for good. Everything that happens to a pot is a new row in `events.csv`, so the history is never overwritten. Greenhouse temperatures go in `temperatures.csv`.

This design handles the situations the lab actually runs into:
- **Partial harvests** (e.g. papaya, where some roots are taken and the plant is put back): each harvest is its own event, and the pot stays active.
- **Plants that die before harvest:** recorded as a `plant_died` event, so the survival analysis counts them. Leaving them out would make forecasts too optimistic.
- **Egg vs. vermiform inoculum:** stored separately, since egg inoculum is less certain.

## `pots.csv`: one row per pot

| Column | Type | Description / allowed values |
|---|---|---|
| `pot_id` | text | Unique ID written on the pot tag, e.g. `RR-PAP-2026-014`. Never reused. |
| `nematode_species` | controlled | `Rotylenchulus reniformis`, `Meloidogyne incognita`, `Meloidogyne javanica`, `Meloidogyne arenaria`, `Radopholus similis` |
| `population` | text | Isolate or population name, if the lab keeps more than one (e.g. `Poamoho`). Blank if only one. |
| `host_species` | controlled | `Carica papaya`, `Ipomoea batatas`, `Solanum lycopersicum`, `Beta vulgaris`, `Coleus sp.`, `Corchorus sp.` (jute), `Anthurium sp.` |
| `host_cultivar` | text | e.g. `Beauregard`, `Pixie`. Blank if unknown. |
| `greenhouse` | controlled | Greenhouse name (e.g. `GH-cool`, `GH-hot`). Must match `temperatures.csv`. |
| `seeded_date` | date | Date seeded in the peat tray, if known. YYYY-MM-DD. |
| `transplant_date` | date | Date moved to sterile sand–soil mix. |
| `inoculation_date` | date | Date nematodes were added. |
| `inoculum_stage` | controlled | `vermiform`, `eggs` |
| `inoculum_count` | integer | Number of nematodes or eggs added (typically 200–500). |
| `inoculum_source_pot` | text | `pot_id` the inoculum came from, if known. Lets you trace a culture's lineage. |
| `notes` | text | Free text. |

`status` is not stored. The app works it out from the events (active, harvested, died, discarded), so it can never disagree with the event log.

## `events.csv`: append-only log

| Column | Type | Description / allowed values |
|---|---|---|
| `event_id` | integer | Running number. |
| `pot_id` | text | Must exist in `pots.csv`. |
| `date` | date | YYYY-MM-DD |
| `event_type` | controlled | `partial_harvest` (roots sampled, plant returned to pot), `final_harvest` (pot ended), `plant_died`, `gall_check`, `discarded`, `note` |
| `eggs_counted` | integer | Total eggs extracted (NaOCl method). Required for harvests. |
| `root_fresh_weight_g` | number | Fresh weight of roots processed. Optional, but it allows eggs per gram of root, which compares better across hosts. |
| `gall_rating` | number | 0–10 gall index for `gall_check` events (Meloidogyne). Optional. |
| `extraction_method` | text | Default `NaOCl shake`. |
| `recorded_by` | text | Initials. |
| `notes` | text | Free text. |

## `temperatures.csv`: greenhouse logger data

| Column | Type | Description |
|---|---|---|
| `greenhouse` | text | Matches `pots.greenhouse`. |
| `timestamp` | datetime | YYYY-MM-DD HH:MM |
| `temp_c` | number | Air temperature in °C. The app displays °F as well. |

## Derived values (calculated by the app, never typed in)

- **Days post-inoculation (DPI):** event date minus inoculation date.
- **Degree-days since inoculation:** accumulated from `temperatures.csv` above a base temperature for each species. This is the forecast's time scale.
- **Reproduction factor (Rf):** eggs counted ÷ inoculum count. Flagged as approximate when the inoculum was eggs.
- **Status:** worked out from the latest event.

## Simulated data

Until the lab has enough real records, the app runs on simulated data generated by `src/simulate.py`. Simulated rows have `pot_id` values starting with `SIM-`, and the app labels them as simulated everywhere they appear.
